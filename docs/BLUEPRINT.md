# Shorts Studio: a zero-cost local AI video pipeline

You give it a topic. It produces a publish-ready 9:16 Short (1080x1920, 30–90 s) with a voiceover, animated visuals, word-highlighted captions, music, sound effects, a thumbnail and post text. Everything runs on your Mac. Nothing is paid, nothing adds a watermark, and there are no usage caps.

```
python studio.py "Why the Moon is slowly drifting away from Earth" --style pixel
```

Built and tested on a MacBook Air (M5, 16 GB RAM), November 2026.

---

## 1. The stack and why each piece was chosen

| Stage | Tool | License / cost | Runs | Why |
|---|---|---|---|---|
| Research | Wikipedia API | Free, no key. Content is CC BY-SA | Online | Gives the script real facts to work from (see section 6) |
| Script | **Ollama + Qwen3 8B** | Apache 2.0 | Local, about 5 GB RAM | The best writing model that fits comfortably in 16 GB. Structured JSON output |
| Images | **mflux + Z-Image Turbo** (4-bit) | Apache 2.0 (model), MIT (mflux) | Local, MLX-native | Top-quality open image model that fits in 16 GB. 9 steps. Commercial use allowed |
| Voice | **Kokoro-82M via mlx-audio** | Apache 2.0 | Local | Near-commercial-quality TTS with a tiny model, about 50 voices. Commercial use allowed |
| Voice fallback | macOS `say` | Built in | Local | Always works |
| Music | Generated by code (chiptune or ambient pad) | Yours | Local | No copyright claims, ever. You can also pass `--music file.mp3` |
| SFX | Generated by code (blips, whooshes) | Yours | Local | Same reason |
| Animation | Python/Pillow: camera moves, pixel pans, whiteboard reveal, transitions | Yours | Local | Fast and deterministic, and doesn't need a GPU video model |
| Captions | Burned in, word by word, with the current word highlighted | Yours | Local | The caption style that holds attention on Shorts |
| Encode | ffmpeg + Apple VideoToolbox (hardware H.264), loudness normalized to -14 LUFS | LGPL/GPL, free | Local | Fast hardware encoding, and the loudness phones expect |

### Rejected or optional, and why

- **AI video models (Wan 2.2, LTX-2, HunyuanVideo)** are open and free, but on a 16 GB fanless Air they take minutes to over an hour per 2–5 s clip, and they often run out of memory. Animated stills look better for explainers and render about 100x faster. If you want an occasional hero clip, use **Draw Things** (free Mac App Store app; local generation is free, and its paid tier only adds cloud compute). Generate a 3–4 s LTX/Wan clip from one of your scene images and drop it in.
- **Remotion** is free only for individuals and companies with 3 or fewer employees. A larger company needs a paid license, so it isn't zero cost in every situation. **Motion Canvas** (MIT) is the truly free alternative if you later want code-driven motion graphics.
- **CapCut, Canva, InVideo, Pictory, Runway, Kling, Pika, ElevenLabs, Suno free tiers** fail the zero-cost test because of credit caps, watermarks, terms that change, non-commercial-only free tiers, or paywalled export.
- **MusicGen / Stable Audio Open**: MusicGen weights are CC BY-NC (non-commercial, so a monetized channel is a problem). Stable Audio Open uses a community license with revenue limits. **ACE-Step 1.5** (MIT) is fine commercially but slow on Apple GPUs (MPS). Use it only if you want AI-generated songs with vocals.
- **Free cloud LLM tiers** (Gemini, Groq, etc.) write better scripts than an 8B local model, but their quotas and terms can change, and some free tiers train on your inputs. They're fine as an optional upgrade but aren't required.

### Free music you can use with `--music`
- **YouTube Audio Library** (YouTube Studio → Audio Library): free, and claim-safe on YouTube. Some tracks require attribution, which goes in the description. It's licensed for YouTube only.
- **Pixabay Music**: free license, including commercial use. Occasional Content ID false positives can be disputed.
- **Free Music Archive / ccMixter**: check each track's CC license and avoid NC tracks if you monetize.

## 2. Hardware reality on a MacBook Air

- **16 GB RAM is the main constraint.** Don't run the LLM and the image model at the same time. The pipeline runs its steps one after another, and Ollama unloads idle models after 5 minutes. Close Chrome tabs while images generate.
- **The fanless chassis throttles** under sustained load. Expect the 2nd–8th images to be a bit slower than the first. Plug in power, and use a hard surface rather than your lap.
- **Disk:** the first Z-Image download is about 31 GB (full precision). After the 4-bit save step below, you only need the 5.5 GB copy in `models/`, and you can delete `~/.cache/huggingface/hub/models--Tongyi-MAI--Z-Image-Turbo` to reclaim about 25 GB. Qwen3 8B is 5 GB.
- **Why the 4-bit save step matters:** without it, mflux loads the full weights and quantizes on every run. Measured on this Air: **25 GB peak memory and heavy swapping**. From the saved 4-bit copy: **8.3 GB peak and 58 s per image**.
- **Measured per-video time (M5 Air, 50 s video, 9 scenes):** 4–7 min for the script (research, draft and fact-check), under 1 min for voice, 9 min for images (58 s each), and **7 s** to render. **About 12 min for images and render, plus the script step.**
- **8 GB Macs:** use `--llm qwen3:4b` and add `--low-ram` to the mflux call in `studio.py` (or switch to FLUX.2-klein-4B).

## 3. Install (one time, about 30–60 min, mostly downloads)

```bash
brew install ffmpeg uv ollama
brew services start ollama
ollama pull qwen3:8b

cd ~/Desktop/work/shorts-studio
uv venv -p 3.12 .venv
source .venv/bin/activate
uv pip install mflux mlx-audio "misaki[en]" numpy pillow requests
```

Then save a 4-bit copy of the image model once. This step is essential on 16 GB:

```bash
mflux-save --model z-image-turbo --quantize 4 --path models/z-image-turbo-4bit
```

`studio.py` uses `models/z-image-turbo-4bit` automatically when it exists. Model weights download automatically on first use (Z-Image Turbo from Hugging Face, Kokoro from mlx-community). Neither is gated, so you don't need a Hugging Face account.

## 4. Daily use

```bash
cd ~/Desktop/work/shorts-studio && source .venv/bin/activate

python studio.py "How octopuses taste with their arms" --style cartoon --seconds 50 --voice af_heart
```

Output lands in `out/<topic-slug>/`:
- `<title>.mp4`: the final video
- `thumbnail.png`: cover frame with the title
- `post.txt`: title, caption and hashtags, ready to paste
- `script.json`, `notes.txt`, `audio/`, `img/`: intermediate files (every step is cached)

### The review loop (where quality comes from)

Every step caches its output. So the best workflow is:

```bash
python studio.py "TOPIC" --style pixel --stop-after script
# open out/<slug>/script.json and fix facts, sharpen the hook, tweak visuals
python studio.py "TOPIC" --style pixel --stop-after images
# look at out/<slug>/img/, delete any image you dislike
python studio.py "TOPIC" --style pixel --seed 7
# missing images are regenerated with a new seed, then the video renders
```

Useful flags:
- `--redo script|voice|images|render` regenerates one stage
- `--notes facts.txt` adds your own research and always takes priority (the strongest way to guarantee accuracy)
- `--music track.mp3` uses your own music instead of the generated music
- `--voice`: try `am_michael`, `am_puck`, `af_heart`, `af_bella`, `bf_emma` (British), `bm_george`
- `--speed 1.1` is snappier (Shorts reward fast narration)
- `--llm gemma3:12b` swaps the writer model (any Ollama model works)

## 5. Styles

| `--style` | Look | Motion | Transition | Music |
|---|---|---|---|---|
| `pixel` | 16-bit SNES, true hard-edged pixels (generated, then downsampled to a 144x256 grid, palette-quantized to 40 colors, and upscaled with nearest-neighbor) | Pixel-perfect pans | White flash + chiptune blip | Chiptune |
| `cartoon` | Flat 2D explainer, bold outlines | Smooth Ken Burns zoom/pan | Crossfade + whoosh | Ambient pad |
| `whiteboard` | Black marker doodles on white | Hand-wipe reveal, then slow zoom | Hard cut | Ambient pad |
| `papercut` | Layered paper motion graphics | Ken Burns | Slide push | Ambient pad |
| `cinematic` | Dramatic digital painting | Ken Burns | Crossfade | Ambient pad |

Add your own style in `styles.py`. A style is a prompt prefix plus motion, transition and music choices.

**Consistency tricks already built in:** a fixed style prefix on every prompt, one recurring "character" described identically in every scene, sequential seeds, and (for pixel) a shared palette quantization that unifies colors across scenes.

## 6. Accuracy: the honest part

An 8B local model **will** invent numbers. In testing, before grounding was added, it claimed the Moon would be "25% farther in 100 million years". The real figure is about 1%. The pipeline reduces this in three ways:
1. It pulls the two most relevant Wikipedia articles and tells the model to use only those facts.
2. It runs a second fact-check pass with Qwen3's reasoning mode turned on.
3. It writes `script.json` so you can review it before spending image time.

**Always read the script before publishing.** It takes 60 seconds. For high-stakes topics, add `--notes`.

## 7. What makes Shorts perform (baked into the prompt and render)

- **Hook in the first 1–2 s:** a surprising claim or question, with no "hey guys". There's a big on-screen keyword in the first second of every scene.
- **Change the picture every 4–7 s.** The scene length is set to match.
- **Captions stay on screen, 3 words at a time, with the active word highlighted.** They sit at 68% of the height, clear of the platform UI at the bottom and the title at the top.
- **Loop ending:** the final line calls back to the hook or asks a question, which drives replays and comments.
- **30–60 s is the sweet spot.** Use `--seconds 35` for quick facts and `--seconds 75` for stories.
- **Same video on all three platforms:** 1080x1920 H.264/AAC is accepted by YouTube Shorts, Reels and TikTok. Upload natively to each. Don't cross-post a TikTok-watermarked download.

## 8. Automating further (all free)

- **Batch:** put one topic per line in `topics.txt`, then run
  `while read t; do python studio.py "$t" --style pixel; done < topics.txt`
  overnight. One Air makes about 4 videos per hour.
- **Schedule:** use `launchd` or `cron` to run the batch at night while plugged in.
- **Topic ideas:** ask the local model for topic lists, e.g.
  `ollama run qwen3:8b "20 surprising space facts as Shorts titles"`
- **Upload:**
  - The YouTube Data API v3 is free. Upload quota was raised in Dec 2025, and 2026 sources report a separate allowance of about 100 uploads a day, but check the Quota Calculator in Cloud Console. It needs a Google Cloud project with OAuth. Videos uploaded from unverified API projects are locked private until the project passes Google's audit, so for a personal channel it's usually simpler to upload in YouTube Studio and use its free scheduler.
  - Instagram (Graph API) and TikTok (Content Posting API) both require an app review. Their free native schedulers (Meta Business Suite, TikTok web) are the practical zero-cost route.
- **Better captions timing:** captions are currently timed by word length within each scene's measured audio, which is accurate enough with Kokoro's even pacing. For exact word timing, `uv pip install mlx-whisper` and align each `audio/NN.wav`.

## 9. Hidden costs and limits checklist

- Electricity and time are the only real costs.
- Licenses: Z-Image Turbo (Apache 2.0), Kokoro (Apache 2.0), Qwen3 (Apache 2.0), mflux (MIT), and mlx-audio, Pillow and numpy are all open source. Generated music and SFX are your own. **All of them allow monetized commercial use.**
- **Not** covered: FLUX.1-dev and FLUX.2-dev weights (non-commercial), MusicGen weights (non-commercial), and Remotion for companies with 4+ employees.
- Platform policy: YouTube requires you to disclose *realistic* altered or synthetic content. Clearly stylized animation like pixel art or cartoons generally doesn't need the label, but check the toggle when you upload anything photoreal. Mass-produced repetitive content can be demonetized under YouTube's "inauthentic content" policy, so add your own angle, voice and editing choices.
- Wikipedia text is CC BY-SA. Facts can't be copyrighted, but don't read articles out word for word.
